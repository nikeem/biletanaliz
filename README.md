# biletanaliz

Streamlit-приложение для анализа покупателей билетов. 1 xlsx-файл = 1 матч, дата матча берётся из имени файла (`05_09_2026.xlsx`).

## Форматы файлов

- **Простой:** одна колонка «Email покупателя», строка = одно место.
- **Подробный:** Сектор | Ряд | Место | Дата/время продажи | Email покупателя.

Если один матч загружен в двух форматах, используется подробный.

## Вкладки

- **Подозрительные** — рейтинг email по признакам перекупа (нужен подробный формат).
- **Покупатель** — карточка email: признаки по матчам, все заказы по времени, связанные аккаунты.
- **Связанные аккаунты** — справочно, без баллов.
- **Посещаемость** — кто был на n, n-1, n-2 … матчах.
- **Матчи** — сводка по матчам.

## Как считаются признаки

Заказ = все места, купленные с одного email на один матч в одну и ту же минуту.
Места «рядом» = тот же сектор, соседний ряд (±1), номер места ±2 (настраивается).

Для каждого email и матча:

| Признак | По умолчанию | Вес |
|---|---|---|
| Разброс по блокам | 3+ отдельные группы мест | 2 |
| Растянуто по дням | 2+ заказа, между первым и последним 1+ день | 2 |
| Много заказов | 3+ заказа | 2 |
| 5+ мест не рядом | 5+ мест, минимум 2 группы | 1 |

Балл email = сумма весов по всем матчам. Пороги меняются в боковой панели.

Связанные аккаунты (в балл не входят): соседние места в одном ряду, купленные с разных email
с разницей до 5 минут; одинаковое имя ящика на разных доменах; имя ящика отличается на 1 символ.

## Запуск

```bash
pip install -r requirements.txt
streamlit run app.py
```

Деплой: share.streamlit.io → репозиторий `nikeem/biletanaliz`, ветка `main`, файл `app.py`.
